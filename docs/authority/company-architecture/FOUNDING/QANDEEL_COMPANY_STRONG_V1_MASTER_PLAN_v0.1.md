**Status:** ACTIVE PLANNING / EDITABLE

---

# 1. تعريف Strong v1

Strong v1 هي النسخة التي يمكن لمحمد استخدامها فعليًا لإدارة شركة QANDEEL قبل الإطلاق الرسمي، مع:

- موظفين دائمين Persistent Employees.
- تدريب واعتماد قبل الخدمة.
- ذاكرة واستمرارية عبر Sessions.
- Canonical Company Truth.
- أقسام ومديرين وتفويض.
- تواصل Agent-to-Agent.
- Work lifecycle.
- مراجعة وجودة وصلاحيات.
- Local-first runtime على جهاز قنديل.
- Founder Command Center.
- Reporting وPerformance.
- Learning loop وتطوير الموظفين.
- Pilot حقيقي قبل الإطلاق.

---

# 2. طريقة قياس التقدم

لا تُقاس النسبة بعدد الملفات أو Tasks.

كل Stage له وزن.  
لا يُحتسب الوزن إلا عند إغلاق Gate الخاص به.

الحالات:

- NOT STARTED
- RESEARCH
- DISCUSSION
- DECISION PENDING
- APPROVED
- IN BUILD
- IN REVIEW
- CLOSED / ACCEPTED
- FROZEN
- REOPENED
- BLOCKED

إذا اكتشفنا مرحلة مفقودة:
1. تُضاف فورًا.
2. يُعمل Impact Analysis.
3. تُعاد موازنة النسب.
4. لا نخفي أثرها للمحافظة على نسبة تقدم قديمة.

# 5. Missing-Stage Protocol

إذا اكتشفنا لاحقًا شيئًا نسيناه:

1. لا نضغطه قسرًا داخل Stage غير مناسبة.
2. نسجله في `DISCOVERED_GAPS`.
3. نعمل Impact Review.
4. نقرر:
   - Sub-stage جديد
   - Stage جديد
   - Cross-cutting track
   - Deferred post-v1
5. نعدّل الأوزان إذا تغير حجم Strong v1.
6. نكتب السبب في Change Log.
7. نحدّث Checkpoint Register.

الهدف هو **صحة الخطة، لا الحفاظ على شكلها الأصلي**.

# 8. Definition of Strong v1 Done

Strong v1 لا تغلق إلا إذا:

1. الموظف يستمر عبر session/model restart.
2. الموظف لا ينسى دوره ومديره وصلاحياته.
3. الموظف يميز memory عن canonical truth.
4. الموظفون يتواصلون ويسألون ويستأنفون العمل.
5. المدير يدير فريقًا حقيقيًا.
6. Founder يستطيع الإدارة من خلال المديرين.
7. الموظفون تم تدريبهم واعتمادهم.
8. الموظفون يتعلمون من الأخطاء بطريقة مضبوطة.
9. الصلاحيات enforced وليست مجرد prompts.
10. العمل والمراجعة والقرارات قابلة للتتبع.
11. الشركة قابلة للنسخ الاحتياطي والاستعادة.
12. Founder Command Center يعطي صورة صحيحة.
13. Pilot حقيقي قبل الإطلاق يثبت الاستمرارية.
14. لا يحتاج محمد لإعادة شرح QANDEEL لكل موظف في كل Session.
